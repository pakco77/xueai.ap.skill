# AI Model Cost Selector｜AI 模型成本选择器

> 一句话价值：先找出满足任务约束的最低模型层级，再用本次运行核验的官方价格计算可信的月成本区间。

[直接查看 `SKILL.md`](../skills/ai-model-cost-selector/SKILL.md) · [打开完整 Skill 目录](../skills/ai-model-cost-selector/)

## 它适合解决什么

当模型账单说不清、上下文越来越长，或团队正在争论“升级模型还是做路由”时，用它把质量约束、调用链和真实成本放到同一张账上。

### 服务场景

- 新产品选型：依据上下文、模态、质量、延迟、隐私和预算筛选模型层级。
- 月度预算：按 low / base / high 三种场景估算请求量变化后的成本范围。
- Agent 成本拆解：展开 Router、Planner、工具循环、Generator 与 Evaluator 的隐藏调用。
- 成本异常诊断：区分输入、输出、图片、重试或调用次数哪个才是主因。
- 优化取舍：判断缓存、压缩、路由和降级应当现在做、收集数据后做，还是暂不做。

## 30 秒开始

Hermes / Claude Code：

```text
/ai-model-cost-selector 请按下面工作负载选择模型层级并估算月成本。必须在本次运行查询官方定价与模型文档，附 source_url 和 verified_at，不要使用记忆价格：<工作负载>
```

Codex：

```text
$ai-model-cost-selector 分析 <产品或调用链> 的 low/base/high 月成本；先运行时核验官方能力与价格，再判断缓存、压缩、路由和降级是否值得做。
```

## 最好提供哪些输入

- 请求量与统计周期、平均输入与输出 Token、必需的最大上下文长度；
- 图片数量、尺寸、质量或服务商计费单位，以及延迟与质量目标；
- 月预算、币种、地区和每个用户请求触发的模型调用数；
- 可缓存前缀比例、重试率、fallback 触发率与固定工具费用。

信息不全也可以开始，但缺口会变成明确标注的 low / base / high 假设，不会被藏进一个看似精确的数字里。

## 效果与输出

结果包括适合的能力层级、月成本区间、成本构成、优化建议、值得做的工作、过度工程判断，以及单独的价格核验记录。

模型的“必需上下文容量”只用于能力筛选；实际平均输入 Token 才进入账单。每个用户动作若包含多次模型调用，也会先展开再计算。计算方法见 [运行时成本方法](../skills/ai-model-cost-selector/references/cost-method.md)，附带的 [计算器](../skills/ai-model-cost-selector/scripts/cost_calculator.py) 不包含模型目录或默认价格。

## Demo

### 输入

```text
中文客服 Agent 的月请求 base 为 80,000，low/high 为 50,000/130,000；平均输入 9,000 Token、输出 900 Token，需要 64k 上下文，约 15% 请求带两张图。
每个请求通常调用 Planner、Generator 各一次，额外重试率约 4%，延迟目标 P95 < 8 秒，月预算 6,000 元；请判断缓存或大小模型路由是否值得做。
必须在本次运行查询服务商官方定价页和模型文档；不要沿用历史价格或固定候选清单。
```

优化判断:
  缓存: "收集数据后做；先测稳定重复前缀与命中率"
  路由: "暂不做；先用任务集确认低层级能否覆盖简单请求"
价格核验:
  lookup_mode: "runtime_official_only"
  candidate: "<本次运行从官方资料核验后填写>"

  currency_and_unit: "<官方币种与计费单位>"

## 验收标准

- 每个被推荐的当前型号都同时通过上下文、模态、质量、延迟、隐私和预算筛选。
- 每条价格事实都有本次运行访问的官方 `source_url` 与含时区的 ISO 8601 `verified_at`。
- 价格无法官方核验、仅账号可见或来源冲突时，明确标为 `unverified`，不输出伪精确金额。
- 成本按 low / base / high 展示，并公开请求量、Token、调用数、重试、缓存、图片与 fallback 假设。
- Provider 声明、公开 benchmark、本地评测、生产数据和成本估算保持分层，不互相冒充。
- 每项优化都有预期影响、实施维护成本、前置证据、质量或延迟风险和明确处置结论。

## 边界

- Skill 不内置、不复用任何服务商价格、可用型号、上下文上限或图片计费规则。
- 搜索摘要、博客、排行榜和聚合站只能作为线索，不能作为价格证据。
- 若需要汇率换算，汇率来源也必须单独核验并记录自己的 `verified_at`。
- 不因名气或单价直接选模型；质量差异可能改变选择时，应先跑小型任务集。
- 低流量下的复杂路由、没有稳定重复前缀的缓存，以及为理论最大上下文设计的压缩，都可能属于过度工程。
