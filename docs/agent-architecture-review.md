# Agent Architecture Review｜Agent 架构审查

> 一句话价值：从 PRD、架构图、代码或产品流程出发，找出 Agent 系统真正的可靠性缺口，并给出最小、可验证的修复动作。

[直接查看 `SKILL.md`](../skills/agent-architecture-review/SKILL.md) · [打开完整 Skill 目录](../skills/agent-architecture-review/)

## 它适合解决什么

当一个 AI 功能已经不只是“一段 Prompt”，却又说不清为什么不稳定时，用它做一次证据优先的架构体检。

### 服务场景

- PRD 评审：上线前检查上下文、工具、权限、评测与恢复机制是否闭环。
- 架构复盘：判断长 Prompt 是合理方案，还是正在替代本该由系统承担的约束。
- 代码库审查：沿真实调用链定位工具副作用、状态持久化与失败恢复问题。
- 单 Agent / 多 Agent 决策：用并发、隔离、独立评测和失败边界证明是否需要拆分。
- 长任务设计：检查 checkpoint、幂等重放、取消、重试和跨进程恢复。

## 30 秒开始

Hermes / Claude Code：

```text
/agent-architecture-review 请只读审查这个项目：<PRD、架构图、目录或仓库路径>。重点检查 <最担心的问题>，给出最小修复动作，不要改文件。
```

Codex：

```text
$agent-architecture-review 请只读审查 <目录或文档路径>，沿真实执行链检查八道门，并区分设计声明、代码证据、运行证据和端到端证据。
```

## 最好提供哪些输入

- PRD 或需求说明；
- 架构图；
- 代码目录或仓库；
- 产品流程、录屏或关键步骤描述。

若方便，再补充产品目标、用户关键路径、外部写入动作、数据敏感性、运行时日志、已知故障和上线约束。缺失信息不会被脑补，而会明确标为 `未验证`。

## 效果与输出

输出固定收敛为六部分：

1. `极简结论`：3–6 行可直接转发的总体判断；
2. `架构风险`：证据、缺失证据、失败方式与严重度；
3. `保留什么`：已有且真正降低风险或复杂度的设计；
4. `改什么`：只列具体修改；
5. `为什么`：每项修改对应哪个已证明的风险；
6. `最小修复动作`：最小可逆动作，以及证明它有效的检查。

完整审查会逐项覆盖上下文、工具、记忆、Agent 数量、权限审批、评测、长任务恢复和 Prompt/Harness 成熟度。详细门槛见 [审查清单](../skills/agent-architecture-review/references/review-checklist.md)。

## Demo

### 输入

```text
请只读审查合同审批 Agent：它读取合同和内部知识库，生成意见后发到企业群；目前采用 Planner、Executor、Reviewer 三个 Agent，审批人在任务开始时统一授权。
长任务失败后只能重跑，没有 checkpoint；现有评测仅含 20 条正常合同的回答准确率。
请判断多 Agent 是否必要，以及现在属于 Prompt 还是 Harness。不要修改代码。
```

### 输出节选

```text
极简结论
- 总体风险：高；当前属于「部分 Harness」。
- 三 Agent 的独立权限、独立失败边界与并发收益尚未得到证据支持。
- 发送企业群属于外部写入，任务开始时的统一授权不能替代发送前确认。
- 最小修复：先增加“发送目标 + 内容预览 + 当下确认”门槛，并持久化发送前 checkpoint。

架构风险
1. [高] 审批时点过早：执行期间目标或内容可能变化，存在误发风险。
2. [高] 无可恢复 checkpoint：重跑可能重复工具调用或产生不一致结果。
3. [中] 评测只覆盖正常路径：权限拒绝、工具超时、截断和恢复均未验证。
```

## 验收标准

- 八道门均有 `通过`、`风险`、`未验证` 或 `不适用` 状态。
- 每个风险都能指出证据、可能的失败方式和最小修复，而非泛泛建议。
- 明确给出 `Prompt 足够`、`Prompt 过载`、`部分 Harness` 或 `已有 Harness` 分类。
- 不把设计文档中的声明当成已实现行为，也不把本地测试当成线上端到端结果。
- 多 Agent、长期记忆或平台重写必须由真实需求证明，不能凭“更先进”推荐。
- 最小修复包含一个可运行或可观察的验收检查。

## 边界

- 默认只读；未被明确要求时，不修改代码、PRD、配置、生产系统或外部数据。
- 它是架构可靠性审查，不等同于渗透测试、法律意见、合规认证或正式安全审计。
- 材料不足时会标记 `未验证`，不会制造确定性结论。
- 它优先选择能满足需求的最简单层级：确定性代码、单次结构化调用、单 Agent、持久工作流，最后才是多 Agent。
- 若要证明真实用户侧效果，仍需在目标环境完成相应的运行与端到端验证。
